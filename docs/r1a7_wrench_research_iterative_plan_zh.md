# R1-A7 扳手工具操作研究方案

## 文档定位

本文档不是把“迭代”本身作为研究方案，而是给出当前最适合 R1-A7 真实硬件条件的扳手工具操作研究方案。

Codex 的职责是持续执行以下闭环：

```text
设计研究方案 -> 严格评审 -> 找出问题 -> 修改方案 -> 再评审 -> 再修改 -> 收敛到最适合当前硬件和硕士周期的方案
```

因此，本文档包含两部分：

1. `当前推荐研究方案`：当前应执行和写入论文主线的方案。
2. `Codex 评审与优化记录`：保留每轮方案为什么被否定、修改或收敛，供后续继续迭代。

## 当前硬件约束

- 机器人：Unitree R1-A7，双臂与内走线 Dex1 夹爪。
- 已验证能力：Quest/手柄遥操作双臂，夹爪通过 `rt/lowcmd` 低层电机 `31,33` 控制，只读订阅 `rt/lowstate` 可记录真实状态。
- 当前限制：相机暂不可作为可靠输入；新扳手 FSM 不能直接控制真机；力/力矩反馈与接触检测阈值未确认。
- 当前工程原则：真机运动只走 `tools/r1a7_vr_dual_arm_g1ik_real.py`；扳手项目先只做只读记录、状态标注、keyframe 与离线分析。

## 市面研究方案调研

详见 `docs/r1a7_wrench_market_research_survey_zh.md`。调研结论是：R1-A7 具体型号公开成熟案例较少，本项目应参考 Unitree G1/H1、XR 遥操作、LeRobot/ACT/Diffusion Policy、视觉定位 + IK 和接触丰富操作等通用路线，但当前主线应优先采用固定工装、Quest 遥操作采集、只读状态记录、关键帧状态机和对准/套入搜索策略。

## 当前推荐研究方案

### 研究题目建议

面向 R1-A7 人形机器人的分阶段扳手工具操作方法研究。

更聚焦的论文题目可以是：

面向无力传感器条件的人形机器人扳手-螺母对准与操作策略研究。

### 核心研究问题

在 R1-A7 当前硬件条件下，研究重点不应是一开始完成全自主视觉-双臂-力控系统，而应收敛为：

如何让 R1-A7 在固定工装和弱感知条件下，通过分阶段状态机、遥操作示教数据和保守搜索策略，稳定完成扳手抓取、移动、对准、套入和短角度旋转，并用定量实验证明对准与失败恢复策略的有效性。

### 主线方案

1. 右臂优先，固定螺母工装，扳手初始位姿可控。
2. 用 Quest 遥操作完成真实动作，扳手项目并行只读记录 `rt/lowstate`。
3. 从示教中提取关键帧与阶段标签：`PRE_GRASP`、`GRASP`、`LIFT`、`TRANSFER_SAFE`、`PRE_NUT`、`CONTACT_START`、`ROTATE_START`、`ROTATE_END`。
4. 先形成传统 keyframe/state-machine baseline：人工标定目标、低速位置控制、固定搜索模板。
5. 研究重点放在“无力传感器条件下的扳手-螺母精确对准与失败恢复”：比较无搜索、线性搜索、小扰动搜索和示教统计偏置。
6. 学习方法只用于窄阶段：从示教数据学习 `PRE_NUT -> CONTACT_START` 的小范围 `delta_joint` 或 `delta_ee_pose` 修正，不学习完整任务。
7. 双臂作为扩展：左臂固定工件或辅助稳定，但硕士主结果允许右臂完成核心扳手操作。
8. 视觉作为扩展：先 AprilTag/ArUco 标定螺母/工装坐标，再考虑检测或 6D pose。

### 论文贡献收敛

推荐主贡献：

R1-A7 在无可靠视觉和无力传感器反馈条件下，面向扳手-螺母富接触任务的分阶段工具操作 baseline，以及针对对准/套入阶段的搜索与示教修正策略。

不建议同时声称：

- 完整双臂自主工具使用。
- 端到端视觉动作学习。
- 通用 6D pose 工具操作。
- 高性能力控或阻抗控制。

这些方向可以放在扩展实验或未来工作。

### 推荐技术路线

| 路线 | 内容 | 当前定位 |
| --- | --- | --- |
| 传统控制 | 人工标定/标记、IK、轨迹、状态机、搜索 | 必须先做通，作为 baseline |
| 示教 + 模仿学习 | Quest 示教采集，BC/ACT/Diffusion 学策略 | 只做窄阶段 BC，不做完整端到端 |
| Hybrid 混合方法 | 传统方法做大范围运动，学习或统计策略修正对准/套入 | 推荐作为硕士论文主线 |

### 单臂与双臂结论

- 主路线：右臂单臂完成核心扳手操作，螺母和工件固定在实验台。
- 双臂扩展：左臂固定工件或作为安全辅助姿态，不作为第一阶段必需能力。
- 理由：双臂能提高论文叙事，但会显著增加控制、碰撞和失败归因难度；硕士阶段应先证明工具抓取、对准、套入、旋转闭环。

### 数据结构

每个 timestep 至少记录：

- `timestamp`
- `left_arm_joint_position[7]`
- `right_arm_joint_position[7]`
- `left_gripper_position`
- `right_gripper_position`
- `communication_ok`
- `task_phase`
- `operator_event`
- `success_label`

后续相机恢复后追加：

- `head_rgb`
- `wrist_rgb`
- `camera_intrinsic`
- `T_base_camera`
- `T_base_nut`
- `T_base_wrench`

学习输入输出先限定为：

- Observation：最近 N 帧右臂关节、夹爪状态、阶段标签、人工给定误差或标记位姿。
- Action：小范围 `delta_joint[7]` 或 `delta_ee_pose`，优先 `delta_joint`，因为当前真实可记录和回放链路更直接。

### 坐标系任务

必须维护：

- `base`
- `torso`
- `left/right_shoulder`
- `left/right_wrist`
- `left/right_ee`
- `left/right_gripper`
- `wrench`
- `nut`
- `workcell`
- `camera`，相机恢复后启用

抓住扳手后需要标定固定变换：

```text
T_base_wrench = T_base_ee * T_ee_wrench
```

第一阶段 `T_ee_wrench` 可通过人工测量和重复示教估计；后续用 AprilTag/ArUco 或工装定位校正。

### 实验指标

- 抓取：成功率、抓取后滑移次数。
- 对准：位置误差、角度误差、调整次数。
- 套入：成功率、用时、最大重试次数。
- 旋转：有效旋转角、脱离次数、完成率。
- 完整任务：总成功率、总耗时、人工干预次数。
- 泛化：扳手位置、螺母位置、扳手朝向、初始手臂姿态的扰动等级。

## Codex 评审与优化记录

以下记录不是最终研究方案本体，而是 Codex 对候选方案进行严格评估、否定、裁剪和优化的过程。后续有新实验结果、硬件变化或代码能力变化时，应继续追加新的 `Version N`。

## Version 1：完整自主扳手系统

### Step 1 方案

机器人自主识别扳手和螺母，规划双臂动作，右手抓扳手，左手稳定工件，完成对准、套入、旋转和重复棘轮式调整。

### Step 2 Reviewer 攻击

1. 过于理想化：是，同时要求视觉、双臂规划、接触操作和旋转策略。
2. 超过硕士工作量：是，风险集中在视觉 6D pose、接触控制和双臂协同。
3. 依赖不存在硬件：是，当前相机不可用，力反馈未确认。
4. 假设未确认接口：是，假设可稳定获得力/接触状态。
5. 数据需求过大：是，若直接学习完整策略，需要大量成功示教。
6. 算力需求：中到高，Diffusion Policy/视觉策略不宜作为第一阶段。
7. 创新点可验证性：弱，系统太大导致每个点都难定量。
8. baseline 不清楚：弱，完整系统没有先做通非学习 baseline。
9. 安全风险：高，自动真机接触动作未经过分阶段验证。

### Step 3 问题分级

- Critical Problems：相机不可用、接触控制未确认、自动真机控制未解锁、双臂全流程复杂度过高。
- Major Problems：实验变量太多，失败原因难归因；学习策略数据量不现实。
- Minor Problems：可以后续补论文指标和日志格式。

### Step 4 处理

- 删除：第一阶段完整自主视觉与双臂接触操作。
- 修改：改为固定工装、人工给定位姿、右臂优先。
- 保留：分阶段任务结构、扳手坐标系、对准/套入/旋转指标。
- 延期：视觉、双臂协同、模仿学习策略。

## Version 2：固定工装 + 右臂传统控制 Baseline

### Step 1 方案

固定扳手和螺母位置，人工标定目标姿态。右臂完成接近、抓取、抬升、移动到螺母前方、低速对准、套入、短角度旋转、退出。左臂只保持安全位。先通过遥操作采集关键姿态，再离线建立 keyframe 状态机。

### Step 2 Reviewer 攻击

1. 可实现性明显提升，但当前新 FSM 仍不能真机发命令。
2. 如果只做人工遥操作，论文价值不足。
3. 无视觉会限制泛化能力。
4. 无力反馈时套入和旋转容易因微小误差失败。
5. 只用右臂可能被质疑不是“双臂机器人”研究。
6. 需要明确如何从示教数据转成 baseline 轨迹。
7. 接触成功/失败检测可能需要人工标注。

### Step 3 问题分级

- Critical Problems：自动执行接口未开放前，不能把 keyframe 状态机用于真机。
- Major Problems：论文创新性不足；对准/套入缺少鲁棒性。
- Minor Problems：双臂扩展可以作为附加实验，不必作为主线。

### Step 4 处理

- 删除：近期自动真机发布 `rt/lowcmd` 的目标。
- 修改：把 Phase 1-3 定义为遥操作数据采集、关键帧提取、离线 replay/mock 验证。
- 保留：固定工装、右臂优先、状态机 baseline。
- 延期：真机自动执行到安全审查通过后再做。

## Version 3：当前推荐方案的收敛版本

### Step 1 方案

主线采用“传统分阶段 baseline + 遥操作数据驱动的关键阶段改进”：

1. 右臂优先，固定螺母工装，扳手初始位姿可控。
2. 用 Quest 遥操作完成真实动作，扳手项目并行只读记录 `rt/lowstate`。
3. 从示教中提取关键帧与阶段标签：`PRE_GRASP`、`GRASP`、`LIFT`、`TRANSFER_SAFE`、`PRE_NUT`、`CONTACT_START`、`ROTATE_START`、`ROTATE_END`。
4. 先形成传统 keyframe/state-machine baseline：人工标定目标、低速位置控制、固定搜索模板。
5. 研究重点收敛到“无力传感器条件下的扳手-螺母精确对准与失败恢复”：比较无搜索、线性搜索、小扰动搜索和示教统计偏置。
6. 学习方法只用于窄阶段：从示教数据学习 `PRE_NUT -> CONTACT_START` 的小范围 delta joint 或 delta EE 修正，不学习完整任务。
7. 双臂作为扩展：左臂固定工件或辅助稳定，但硕士主结果允许右臂完成核心扳手操作。
8. 视觉作为扩展：先 AprilTag/ArUco 标定螺母/工装坐标，再考虑检测或 6D pose。

### Step 2 Reviewer 攻击

1. 是否过于理想化：否，核心依赖已验证遥操作和只读状态。
2. 是否超过硕士工作量：否，学习范围被限制在小范围对准阶段。
3. 是否依赖不存在硬件：否，核心阶段不依赖相机和力传感器。
4. 是否假设未确认接口：部分风险，自动真机执行仍需后续审查；当前阶段只读记录规避该风险。
5. 是否需要无法获得的数据：否，可由 Quest 遥操作采集。
6. 是否需要过多训练数据：否，窄阶段可先用几十到上百条示教做统计/BC 对比。
7. 是否需要高算力：否，优先 MLP/BC 或非学习搜索；Diffusion Policy 只作为远期备选。
8. 创新点是否可验证：是，核心是对准与失败恢复策略在成功率/时间/重试次数上的提升。
9. 是否只是系统集成：风险降低，因为有明确对比和消融。
10. baseline 是否清楚：是，固定工装 + 人工标定 + keyframe FSM + 无搜索/固定搜索。
11. 对比实验是否清楚：是，无搜索、线性搜索、小扰动搜索、示教统计修正、窄阶段 BC。
12. 消融是否清楚：搜索幅度、扰动方向、示教修正、人工标定误差等级。
13. 精度风险：仍存在，但通过固定工装、低速动作和人工标注降低。
14. 安全风险：可控，真机自动控制未通过前不启用。
15. 是否为使用 AI 而使用 AI：否，学习只用于传统方法最弱的窄接触前对准阶段。
16. 是否符合 R1-A7 条件：是，当前只要求双臂/夹爪遥操作和状态记录。
