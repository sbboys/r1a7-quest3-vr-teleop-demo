# R1-A7 扳手任务阶段工作汇总

日期：2026-08-18

## 1. 机器人通讯接口更改

本阶段完成了机器人控制链路从旧接线方式到当前接线方式的切换。

旧方式：

- 机器人网线接 USB 以太网转接器。
- 机器人控制接口曾使用 `enx9c69d37d0967`。
- 该方式在接口切换、路由变化和 Quest 网络同时存在时，容易混淆机器人控制网口和路由/Quest 网口。

当前方式：

- 机器人网线直接接电脑主机独立网口。
- 机器人控制接口使用 `enp6s0`。
- 本机机器人侧地址为 `192.168.123.223/24`。
- 机器人地址为 `192.168.123.161`。
- 路由/Quest 侧仍通过 USB 网卡连接，接口为 `enx9c69d37d0967`，本机地址为 `192.168.1.103/24`。

当前运行原则：

- DDS 机器人控制命令和 `rt/lowstate` 订阅走 `enp6s0`。
- Quest 浏览器访问 `https://192.168.1.103:8012/?ws=wss://192.168.1.103:8012`。
- 每次换线后重新检查 `ip route get 192.168.123.161`，确认路由走机器人侧接口。

## 2. 夹爪抖动问题处理

问题现象：

- VR 扳机持续压到底时，夹爪会继续尝试闭合。
- 扳手阻挡夹爪完全闭合后，位置目标与实际位置持续存在误差。
- 夹爪在目标追赶和物体反作用之间反复调整，导致夹持处抖动，严重时会把扳手弹出。

已完成修改：

- 将低层夹爪默认控制参数调软：速度限制 `1.5`，`kp=8.0`，`kd=1.5`。
- 增加低层夹爪接触保持逻辑 `--lowcmd_gripper_contact_hold`。
- 当扳机大幅闭合、夹爪目标和实际位置存在误差、并且夹爪位置短时间几乎不再变化时，判定为接触阻挡。
- 接触后不再继续向完全闭合目标强追，而是在接触位置附近加一个小的闭合偏置 `--lowcmd_gripper_contact_hold_bias 0.035`，用于柔性保持扳手。
- 日志中增加 `contact_hold_L` 和 `contact_hold_R`，用于确认左右夹爪是否进入接触保持。

当前结论：

- 夹扳手时应使用柔性夹紧保持，而不是持续强制追完全闭合位置。
- 后续如果仍有滑移，优先微调 `contact_hold_bias`、夹爪胶垫和扳手夹持位置，而不是直接大幅提高 `kp`。

## 3. VR 头显和手柄控制更改

目标：

- Quest 不必须一直戴在头上，可以挂在脖子上。
- 进入 VR 页面后，手柄不会立即控制机器人。
- 操作者需要长按右手柄 `A` 才能接管双臂和夹爪。
- 松开 `A` 后机器人保持松开瞬间姿态。
- 再次长按 `A` 后，以机器人当前姿态重新建立跟随基准。

已完成修改：

- 新增 `--arm_enable_button right_ctrl_aButton`，默认长按右手柄 `A` 才允许机器人运动。
- `A` 未按下时，双臂和夹爪保持当前实测状态，不跟随手柄。
- 松开 `A` 时锁定当前双臂姿态，进入 `enable_released_hold`。
- 再次按住 `A` 时，进入 `rearm_hold`，以当前机器人姿态重新接管，避免突跳。
- Quest 姿态断流、退出 VR 或 WebSocket 异常时，双臂保持当前实测姿态，不回到启动初始姿态。

现场验证结论：

- Quest 挂在脖子上仍可使用手柄控制。
- 长按 `A` 控制、松开 `A` 保持、再次长按 `A` 重接管的逻辑已经验证可用。

## 4. 当前推荐启动命令

详见 `docs/r1a7_wrench_next_operator_steps_zh.md`。

核心参数：

```text
--interface enp6s0
--host_ip 192.168.1.103
--arm_enable_button right_ctrl_aButton
--lowcmd_gripper_contact_hold
--lowcmd_gripper_velocity_limit 1.5
--lowcmd_gripper_kp 8.0
--lowcmd_gripper_kd 1.5
```
