# R1-A7 GitHub 仓库管理规范

## 当前定位

本仓库是 R1-A7 长周期研发工作台，覆盖仿真、Quest 3 VR 遥操作、相机控制、扳手任务、细线穿孔、手臂控制台、ACT 复现、双相机视觉伺服和低速控制实验。

2026-10-11 起，`codex/r1a7-workspace-2026-10-11` 作为内容层面的统一工作入口；`main` 仍是独立的早期 Quest 3 演示基线。本次整理不改写历史，也不移动已验证运行路径。

## 内容分层

### 代码

可复现、会运行或被导入的 Python、C++、JavaScript、HTML、Shell、配置和机器人模型文件放在项目目录或共享运行时目录。日期化探针和条件实验脚本放入 `diagnostics/` 或 `experimental/`。

### 文档

稳定入口写入项目 README；操作手册、故障排查、架构、实验结论和交接记录进入 `docs/` 或项目内 `docs/`。原始 Word/PPT 可作为来源记录保留，但必须同时提供可搜索的 Markdown 摘要。

### 数据和结果

少量复核用 JSON、CSV、标定结果可以保留。视频、原始图像集、录制包、数据集、模型和 checkpoint 使用 manifest、Git LFS 或外部存储，不继续直接进入普通 Git 历史。

### 历史内容

旧脚本、失败版本、备份文件和一次性探针进入 `archive/` 或保留在历史 tag/分支中；它们不作为稳定入口。

## 分支流程

1. 从当前统一工作线创建短期功能/实验分支。
2. 一次提交只表达一个可审查目的：功能、实验结果、文档或目录治理。
3. 合并前执行仓库检查、语法检查和真机安全复核。
4. 合并后更新项目 README、`PROJECT_INDEX.md` 和必要的交接文档。
5. 冻结阶段成果时创建 `snapshot/<project>-YYYY-MM-DD` tag。

`main` 与后期研发工作区没有共同祖先。除非另开迁移任务并逐文件审查，否则不得使用 unrelated-histories 强制合并。

## 大文件策略

- 新增单文件默认不超过 20 MiB。
- 视频、bag、权重、checkpoint 和原始数据默认禁止进入普通提交。
- `datasets/README.md`、`checkpoints/README.md` 或项目清单记录文件名、大小、SHA256、采集日期、设备、环境、外部位置和恢复方法。
- 历史中已有大文件暂不执行 `filter-repo`，避免破坏现有提交、分支和链接；历史瘦身需单独备份和审批。

## 真机安全边界

任何会发布 `rt/lowcmd` 或能驱动手臂/夹爪的脚本，入口文档必须说明：

- 是否连接真实机器人；
- 网卡/IP 和 DDS 配置；
- 是否需要停止其他控制程序；
- 初始姿态、速度/力矩限制和工作空间；
- 启动、停止与急停方式；
- 最近一次验证日期和验证条件。

仿真、只读状态、VR 遥操作和真机控制必须显式区分，不能只依靠文件名判断风险。

## GitHub 设置建议

- 当前阶段保持 `main` 不变；统一工作线完成回归后，再决定是否设为默认分支。
- 对最终默认分支启用禁止强推、要求审查、要求检查通过等保护规则。
- 使用 Issue 模板记录缺陷和实验，使用 PR 模板记录风险、验证和回滚方式。
- 不删除旧分支；先打快照 tag、更新 `BRANCH_CATALOG.md`，再进行界面归档。

## 提交前检查

```bash
bash scripts/repository_sanity_check.sh
git diff --check
git status --short
```

真机功能还需按项目操作手册完成硬件回归；语法检查通过不等于真机安全验证通过。
