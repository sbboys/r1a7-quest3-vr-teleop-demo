## 3. 关键定量结果与解释边界

### 3.1 低速控制

历史 Kd2/Kd20/Kd30 数据中的中位 X 速度约为 `4.14/7.93/8.59 mm/s`，低速样本
占比约为 `36.8%/24.4%/13.8%`。这支持把肩俯仰速度反馈设为 Kd30，但不代表
所有起始姿态、方向和负载都已资格化。

恢复的 00:36 CSV 共 323 行，`W` 方向命令 X 位移约 `19.182 mm`、实测约
`13.401 mm`、最大滞后约 `8.192 mm`。因此控制器参数优化不能替代起始姿态、
唯一 LowCmd 发布者和真实末端测量的核验。

### 3.2 视觉伺服速度实验

| 设定档 | 行数 | 平均/P95/最大滞后 (mm) | 结果标签 |
|---:|---:|---:|---|
| 10 mm/s | 1324 | 28.40 / 34.48 / 36.64 | 操作员确认穿孔成功 |
| 15 mm/s | 2253 | 31.10 / 35.63 / 37.20 | 缺失 |
| 25 mm/s | 1305 | 26.43 / 35.87 / 38.14 | 缺失 |

融合器和控制器中的速度值是命令上限或裁剪结果，并非独立测得的 TCP 速度；像素
残差也不能直接当作毫米误差。`STOP` JSON 为零只证明软件输出归零，不证明真实
机械臂物理停止时间。

### 4.2 左右臂对称控制

控制器配置标识为 `dual_arm_kd30_posvel_dqik_symmetric_v1`，主要变化如下：

- 左、右肩俯仰都使用 Kd30；
- DQIK 速度参考和 POSVEL 肩关节补偿跟随当前选择的手臂，不再写死右臂索引；
- 左臂重力前馈比例默认镜像右臂，当前默认仍为 `0.0`；
- 左、右腕部姿态和肘部软约束使用对称参数；
- 切换手臂时清空肩关节 POSVEL 历史，避免跨手臂遗留状态；
- 启动前检查外部 `R1A7_ArmIK.solve_ik()` 是否具备左臂参数，缺失时在取得
  LowCmd 控制权前失败退出。

外部 IK 实现不在本仓库，所需修改已归档为
`transfer_control/patches/r1a7_arm_ik_posture_symmetry_20261016.patch`，应用说明见同目录
`README.md`。当前只完成源码、单元测试、离线 IK 和零运动启动核对；未执行真实
左臂方向点动。

### 4.3 右夹爪闭合端点

### 5.2 单击锁存与速度分层

根据操作员要求，执行按钮从“持续按住”改为“单击开启/再次单击停止”。浏览器每
0.25 s 刷新 0.75 s 租约；控制断开、页面失焦、相机/融合超时、手动运动未停止或
模式/有效源不匹配仍会输出零速度。

`tracking_lag_too_large` 拒绝条件已取消。取消后不再因为累计末端滞后自动拒绝视觉
执行，因此真实测试必须通过低速、短行程和现场急停弥补这一安全裕度。

当前三维合速度上限按融合模式分层：

| 融合模式 | 上限 |
|---|---:|
| `DUAL` / 双目优先 | 10.0 mm/s |
| `EXTERNAL_ONLY` / `WRIST_ONLY` | 2.0 mm/s |
| `BLIND_GRACE` | 0.5 mm/s |
| 其他/状态不匹配 | 0，拒绝执行 |

有效输出仍取“模式上限、控制器上限、视觉建议向量模长”三者中的最小值。分层已做

## 6. 头部相机官方视频路径

控制台已从旧 `VideoClient` 尝试切换到宇树官方 R1-A 视频服务路线：

1. 检查 `enp6s0` 是否具有接收地址 `192.168.123.164`；
2. 保存 `video_hub` 与 `stereo_patch_pc1` 原状态；
3. 停止 `video_hub`，启动 `stereo_patch_pc1`；
4. 在 `192.168.123.164:5001` 接收 RTP/H.264 的 1280×720 图像；
5. 停止预览或启动失败后恢复原服务状态，避免长期影响手机 App。

代码已处理 `ServiceSwitch` 返回 3104 但服务状态实际完成的情况，并为无首帧显示
明确错误。模拟命令、状态恢复逻辑和静态测试可以通过；最近一次真实网络检查仍未
在 UDP 5001 收到 RTP/H.264 首帧。因此“官方路径已接入”不等于“头部相机已修复”。
下一次实机检查仍需确认机器人 Patch、Stereo patch PC1 和 System patch PC4 版本，
以及机器人端确实向 `192.168.123.164` 推流。
